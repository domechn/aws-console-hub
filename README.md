# AWS Console Hub

**把多个 AWS 账号的 Console 放进同一个 macOS 窗口，每个账号独立登录、同时在线。**

浏览器同一个 profile 只能登录一个 AWS 账号，切换要反复登出登录。AWS Console Hub 给每个账号一个独立会话，十几个账号可以同时保持登录，`⌘1-9` 一键切换，`⌘K` 直接跳到任意服务或最近访问过的资源。

> 登录凭证来自你自己配置的「凭证命令」：任何能输出 AWS CLI `credential_process` 格式临时凭证的命令都行（`aws configure export-credentials`、公司内的凭证工具、自己写的脚本……）。应用本身不读取 `~/.aws`。界面为中文，目前只在 macOS 上完整可用。

## 功能

- **多账号并行** — 每个账号独立登录状态，切换不用重新登录。没有侧栏：账号都在顶栏左上角的下拉列表里，Console 占满窗口宽度。
- **⌘K 快速跳转** — 一个搜索框搜服务、账号和最近访问的资源。可以在查询里直接带 region 和账号，例如 `prod lambda tokyo`：在 prod 账号里打开东京区的 Lambda。
- **最近访问与固定** — 在 Console 里打开的资源和页面会自动记录，常用的可以 ★ 固定。它们显示在窗口底部一条单行横向滚动的条里，尽量不占 Console 的高度；`⌘J` 可以整个隐藏。
- **标签页** — 每个账号有自己的标签页；Console 里的 AWS 链接在新标签页打开，其他网站交给系统浏览器。
- **页内搜索** — `⌘F` 查找当前页面内容。
- **自动续期** — 会话快过期时在后台悄悄续上，不打断你正在看的页面；万一被踢出登录，重新登录后会回到原来的页面，而不是首页。
- **EC2 名称显示** — `i-0abc…` 这类 id 自动换成 `Name` 标签。
- **AI 助手** — `⌘I` 打开右侧聊天面板，用中文问当前账号里的资源：「东京区有哪些运行中的 EC2」「这个 Lambda 最近一小时报错几次」「本月成本前五的服务」。默认只读；按账号开启后，助手可以**提出**变更（停实例、改安全组、缩容……），每个变更都由你在确认卡片上两步确认后才执行。
- **本地操作日志（可选分析）** — 记录你的操作习惯，仅存本地，可以用来找出值得做成快捷方式的重复操作。

## 安装

需要 macOS、Node.js ≥ 22.19，以及一条能在终端里拿到临时 AWS 凭证的命令（见下文「凭证命令」）。

```bash
git clone https://github.com/domechn/aws-console-hub.git
cd aws-console-hub
npm install
npm run dev          # 开发模式运行
npm run dist         # 或打包成 macOS 应用（未签名）
```

## 使用

首次启动按引导添加两类账号：

1. **基础账号** — 填 12 位 account id、role 名、默认 region 和凭证命令。这是获取基础凭证的入口，一般只配一次。
2. **要跳转的账号** — 选择上面的基础账号，填目标 account id 和要 assume 的 role。目标 role 需要信任该基础账号。

如果你的凭证命令能直接拿到每个账号的凭证，只配基础账号也可以，每个基础账号本身就能打开 Console。

添加 / 编辑账号时可以先点弹窗左下角的「测试连接」，不用先保存。它用弹窗里填的值把登录流程完整走一遍，逐步显示 ✓ / ✗：执行凭证命令（显示凭证有效期）→ AssumeRole（仅跳转账号，用所选基础账号已保存的命令）→ 身份校验（`sts:GetCallerIdentity` 的账号和 role 是否和填的一致）→ 联邦登录（能否拿到登录 token，以及 Console 会话大约多长）。某一步失败后，后面的步骤跳过不跑。测试不会打开 Console，也不影响已登录的会话；测试没通过也能保存。改了相关字段后，旧的测试结果会被清掉。

之后点顶栏左上角的账号按钮（或按 `⌘⇧A`）打开账号列表，选一个账号就能打开 Console；Console 占满整个窗口宽度。列表里「账号」和「基础账号」分两组，可以按名称 / account id / role 搜索，`↑↓` 选择、`↵` 切换；悬停在账号上可以 ✎ 编辑 / ✕ 删除，底部可以添加账号，或重新登录当前账号。

### 凭证命令

基础账号的凭证命令要在 stdout 输出 AWS CLI [`credential_process`](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sourcing-external.html) 格式的 JSON：

```json
{"Version": 1, "AccessKeyId": "…", "SecretAccessKey": "…", "SessionToken": "…", "Expiration": "2030-01-01T00:00:00Z"}
```

`Version` 可以省略；`SessionToken` 和 `Expiration` 必须有，也就是说只支持临时凭证（Console 联邦登录只接受临时凭证）。

命令里可以用 `{accountId}`、`{role}`、`{region}` 占位符，会替换成该账号填的值；同样的值也放在环境变量 `AWS_HUB_ACCOUNT_ID`、`AWS_HUB_ROLE`、`AWS_HUB_REGION` 里。例如：

```bash
# 用 AWS CLI 已配置好的 profile（SSO、assume role 等都行）
aws configure export-credentials --profile myprofile --format process

# 已经在 ~/.aws/config 里给某个 profile 配了 credential_process，就把那条命令原样填进来
my-credential-helper --account {accountId} --role {role}
```

命令通过你的登录 shell（`$SHELL -lc`）在家目录下运行，`PATH` 取自交互式登录 shell（会读 `~/.zshrc` / `~/.bashrc`），所以从 Dock 启动应用时也能找到你在 shell 配置里加进 `PATH` 的命令（alias 和函数不行）。超时 45 秒。「测试连接」会真的跑一次命令：成功时显示凭证有效期，失败时显示 stderr。stdout 里的密钥任何时候都不会显示。

窗口底部条里固定项排在前面，接着是最近访问（新的在前）；滚轮或触控板左右滑动浏览，悬停在条目上可以 ★ 固定 / ✕ 移除。条隐藏后，点顶栏右侧的时钟按钮或按 `⌘J` 恢复。

### 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `⌘K` | 快速跳转面板 |
| `⌘⇧A` | 账号列表（搜索、切换、添加、编辑账号） |
| `⌘F` | 页内搜索（`↵` / `⇧↵` 上一个 / 下一个，`esc` 关闭） |
| `⌘J` | 显示 / 隐藏底部的最近访问条 |
| `⌘I` | 打开 / 收起 AI 助手面板 |
| `⌘1` – `⌘9` | 切换到第 N 个账号 |
| `⌘W` | 关闭当前标签页 |
| `⌘⇧]` / `⌘⇧[`，`⌃Tab` | 切换标签页 |

### ⌘K 怎么搜

- **region**：支持 id、城市名、机场码，如 `us-east-1` / `virginia` / `iad`。
- **账号**：账号显示名或 12 位 account id。
- **服务**：支持别名，如 `ddb` → DynamoDB，`k8s` → EKS，`cwl` → CloudWatch Logs。
- 空查询只显示最近访问和账号。

### AI 助手

点顶栏最右边的「✦ AI」或按 `⌘I`，Console 右侧会让出一栏聊天面板。Console 只是变窄，不会被遮住；面板左边缘可以拖动调宽（320–640px）。

**配置**：第一次打开时点「打开 AI 设置」（或面板右上角的 ⚙）：

1. 选服务商：DeepSeek、OpenAI、Anthropic、Google Gemini、OpenRouter、AWS Bedrock（见下文），或「OpenAI 兼容（自定义 baseURL）」（公司网关、本地 Ollama 等）。远程地址必须是 `https://`，`http://` 只允许 localhost。
2. 选模型：下拉列表来自内置的模型目录，选中后显示目录单价（每百万 token）。自定义端点手填模型 id。
3. 填 API key，选存储方式：
   - **加密保存**（默认）：用系统钥匙串（macOS Keychain）加密后存在本机，下次启动不用重填。系统钥匙串不可用时只放内存。
   - **仅本次运行**：只在内存里，退出就忘。
   - **密钥命令**：一行 shell 命令，它的输出就是 key，例如 `security find-generic-password -s deepseek -w` 或 `op read op://…`。每次启动运行一次。
4. 点「测试连接」：发一条极短的测试请求，确认 key 有效、模型支持工具调用。

key 只能写入。界面上只显示「已设置 / 未设置」，任何地方都读不回来。

**AWS Bedrock**：默认不用 API key，而是用应用里某个账号的 AWS 凭证调用 Bedrock：

- **Bedrock 使用的账号**：从账号列表里选一个，可以和你正在查询的账号不同（比如固定用一个开通了 Bedrock 的账号）。凭证走和登录 console 相同的流程（凭证命令 / AssumeRole），只在内存里，每次请求前取一次，快过期时会自动续，不写盘、不发给模型。这个账号需要 `bedrock:InvokeModel` 和 `bedrock:InvokeModelWithResponseStream` 权限，并在 Bedrock 控制台开通所用模型的访问权限。Bedrock 请求不会改用本机 `~/.aws` 里、环境变量里的 AWS 凭证或实例角色。
- 也可以把「认证方式」改成 **Bedrock API key（bearer token）**，key 的存储方式和其他服务商一样（需要 `bedrock:CallWithBearerToken` 权限）。
- **Bedrock region**：单独设置，默认 `us-east-1`，和 console 当前的 region 无关。
- **模型 id**：可以从内置目录里选（含 `us.` / `eu.` / `apac.` / `global.` 等跨区域推理配置文件），也可以手填目录里没有的推理配置文件 id 或 ARN；手填的模型价格未知，不计入费用估算（面板显示「价格未知」）。前缀要和 region 匹配，比如 `eu.` 要在欧洲的 region 调用。
- 「测试连接」失败时会给出中文提示：缺权限（附上要放行的资源 ARN）、模型未开通、需要改用推理配置文件、限流、凭证过期、region 不匹配等。

**使用**：在面板里直接提问，`↵` 发送，`⇧↵` 换行；生成过程中可以点「停止」或按 `esc`。助手会显示正在做的查询（如「正在查询 EC2 实例…」），回答支持表格等 markdown，回答里的 Console 链接点击后在当前账号里打开。每个账号的对话分开保存，可以新建、重命名、删除、清空。工具调用显示成一行，点一下可以看完整说明。

**当前页面**：助手知道你正在看哪个 Console 页面。输入框上方的标签显示它这一轮会拿到什么，比如「当前页面：S3 · my-bucket · 对象」；鼠标悬停能看到具体内容。你问「这个桶是干嘛的」「这台实例为什么停了」时，助手会先用查询工具查这个资源（S3 桶会查标签、版本控制、生命周期、加密、公开访问设置和第一页对象列表），而不是看名字猜。

- **每轮自动发送**：当前标签页的地址（只限 Console 页面，去掉登录令牌、签名之类的参数）、页面标题、region，以及从地址识别出的服务、资源类型、资源名和标签页（如「对象」「属性」）。不发送页面内容。不是 Console 的页面什么都不发。每条提问下面会记下当时打开的页面。
- **读取页面内容**：需要页面上显示的东西（列表、状态、报错）而查询工具拿不到时，助手可以调用「读取当前页面」，聊天里会显示「正在读取当前页面…」。它只读屏幕上这个账号的 Console 页面的可见文字和选中的文字，不读输入框、密码框、代码编辑器和隐藏内容；读到的文字先脱敏（access key、session token、长串密钥、「密码 / secret」后面的值），最多约 8KB，只发给模型，不单独保存，审计里只记字数。
- **关闭**：点页面标签上的 ×，这个对话就不再发送页面信息，助手也不能读取页面（可以再点「开启」）。AI 设置 →「数据与隐私」里取消「允许助手读取当前页面内容」，所有对话都不能读取页面内容（地址和标题照常发送）。

**用量和预算**：面板底部显示本对话和本月（所有对话，已删除的也算）的 token 用量和按目录价估算的费用，仅供参考；模型不在价格目录里时显示「价格未知」，不计入费用。AI 设置 →「用量与预算」可以设月度 token 上限和费用上限（默认不限）：用到 80% 开始在面板里提醒，勾选「超出后暂停新的提问」后，超过上限就不能再发新消息（已经执行的变更结果仍会记录下来）。

**卡片**：列资源、汇总成本、需要你填参数时，助手会给出交互卡片：可排序的表格（超过 20 行分页，可「复制为 TSV」）、键值、状态徽标、表单、Console 链接。卡片上的按钮不会执行任何操作：「在 Console 打开」类按钮直接在当前账号打开对应页面；其他按钮只是把你的选择（或表单内容）作为一条消息告诉助手，由它继续查询。每张卡片只能提交一次，之后变灰显示「已处理」；30 分钟后过期，助手发了新卡片替换时旧卡片显示「已被新卡片替代」。卡片里只有 Console 页面的链接可以点。

**快捷回复**：助手问你问题或给出几个选项时（比如「回复『停止』或『终止』」），回复下面会出现最多 4 个按钮，点一下就等于你自己输入这段文字并发送（同样受预算和长度限制），不会自动发送。开始打字、发送消息、出现新的卡片或审批时按钮就消失；重新打开对话时只有最后一条回复还会显示。快捷回复不能批准或确认任何东西，审批和变更只能在各自的卡片上点。AI 设置 →「数据与隐私」里取消「回复后显示快捷回复」就不再出现（默认开启）。

**批量任务一次完成（运行脚本）**：「每个桶有没有打标签」「所有 region 有多少台实例、按类型统计」「翻完所有页再汇总」这类要查很多次的问题，助手不会一个一个地调用工具，而是写一小段只读的 JavaScript 一次跑完（整段脚本只算 1 次工具调用）。聊天里显示一行「运行脚本 · 12 次调用」，点开能看到它调用了哪些操作（如 `s3:GetBucketTagging ×11`）和完整的脚本代码。脚本里的每次查询和普通查询一样：自动执行 / 先问你的规则不变，审批卡会写明「来自脚本（run_script）」；同一个脚本里同一种普通查询你允许一次，脚本里后面的同类查询就不再逐个问你（敏感读取、带 URL 或别的账号资源的仍然每次都问）。脚本**只能读**，写操作一律拒绝，变更还是走确认卡片。脚本跑在隔离的沙箱里（QuickJS / WebAssembly）：没有文件、网络、进程和定时器，只能通过应用提供的查询函数访问 AWS；单个脚本最多 60 秒（等你审批的时间不算）、300 次查询、同时 8 个、64 MB 内存、代码 8000 字符，返回给模型的结果超过约 12 KB 会截断；点「停止」立即终止脚本和进行中的查询。审计里只记脚本的 hash、长度和调用了哪些操作、各几次，不记代码、参数和结果。

**默认只读**：每个账号默认只读，助手只能查询。查成本（Cost Explorer）时 AWS 每次请求收约 0.01 美元，所以助手只在你问成本时才查，每个对话最多 10 次。

**什么自动执行，什么先问你**：

- **自动执行**：EC2、S3、Lambda、RDS、CloudWatch、Logs、ECS、DynamoDB、CloudFormation、IAM、STS（只有 GetCallerIdentity）、Auto Scaling 的普通查询（`Describe*` / `List*` / `Get*` 等），以及面板里的专用查询工具。
- **先问你（审批卡）**：其他服务的查询（SQS、SNS、KMS、Route 53、EKS、ECR、ELB、API Gateway、EventBridge、Step Functions、CloudTrail、ElastiCache、Kinesis、GuardDuty、Organizations、ACM、CloudFront、SSM、Secrets Manager）；敏感读取（密钥、SSM SecureString、S3 对象内容、DynamoDB 表数据（只允许 SELECT）、日志正文、实例密码 / 启动脚本、签发临时凭证、命令输出等）；参数里有 URL、别的账号的资源、或者不是本账号的桶。名称看不出是不是只读的操作不走审批卡，只能作为「通用请求」提出（要输入操作名）。助手会暂停，面板里出现一张盾牌图标的「需要你的审批」卡片：操作、账号和 region、应用为什么要问你（如「sqs 不在默认自动允许的服务里，需要你确认」）、助手给出的理由（标明是助手说的）、**将原样发送的参数**（只有密码、密钥这类值显示为「已隐藏 · N 个字符」；没有参数时写「无参数」）、请求 ID 和参数校验值。按钮：「允许一次」「拒绝」（卡片上按 esc 也是拒绝），下面一行较淡的「本对话中始终允许 service:action（此账号 · 此区域）」（只有普通查询才有）。倒计时写着「4:53 后自动拒绝」，最后一分钟变红；不处理视为拒绝，点「停止」也会作废。拒绝后助手会收到「用户拒绝了这次调用」，10 分钟内同一个操作不会再来问你。
- **列表以外的服务**：应用直接告诉助手「暂不支持执行 xxx」，不会出现卡片。
- 允许之后的结果照样脱敏（密码、密钥、SecureString、私钥等显示为 `[redacted]`）和截断，再发给你选的模型服务商。S3 对象最多读前 16 KB。

**查看和撤销「一直允许」**：面板顶部会列出本对话已允许的动作（服务:操作:region，不限参数），点 × 撤销；AI 设置 →「本对话已允许的动作」列出所有对话的。它只在内存里，删除对话或重启应用后失效。审批卡和自动放行都会记进审计。

**让助手提出变更**：点面板顶部的「只读」（或在账号设置里勾选「允许 AI 助手提出变更」），看完提示后开启，徽标变成「可提议变更」。之后你可以说「把 web-1 停掉」，助手会**提出**一个变更，不会直接执行：

1. 面板里出现一张确认卡片（带锁图标，由应用生成，助手画不出来）：风险等级、一句话说明（「在 internal-tools · ap-northeast-1 创建 1 台 t4g.small」）和按变更类型排好的内容（应用自己读取的当前状态，不是助手说的）：新建列出实例类型（vCPU / 内存）、镜像、子网和可用区、安全组、标签、预估月费；修改是「项目 / 当前 / 改为」表格，只列会变的项，新值高亮；启停是「运行中 → 已停止」；删除列出会删掉的东西、无法恢复的提醒和会保留的东西（快照、EBS 卷、EIP）。长内容可以展开，密钥和环境变量的值照样隐藏。接着是影响（停机、费用、数据、依赖、影响范围、能否恢复）、账号、region、预检结果、10 分钟倒计时。预检：EC2 先用 DryRun 检查权限和参数；其他服务没有 DryRun，应用用 `iam:SimulatePrincipalPolicy` 模拟一次当前 role 的权限（只读，需要这个权限；没有时卡片上写「无法预检权限」，不影响提案）。模拟结果只是参考，显示「可能没有权限」时仍可以确认，AWS 会在执行时做最终判断。顶部的横幅提示有几个提案在等你确认，点「查看」跳到卡片。
2. 点「确认执行…」展开最后一步，再点「我确认，立即执行」。高风险和破坏性操作（终止、删除、对公网开放 SSH 等）要先输入资源 id 或名称。
3. 应用执行前会再检查一遍：账号是否仍允许变更、资源状态有没有变（变了就不执行，提示你重新生成）、凭证是不是这个账号的。执行后显示结果卡（成功 / 失败 + Request ID），助手再用一句话总结。失败不会自动重试。

可以提议的操作（30 项）：

- **EC2**：启动 / 停止 / 重启 / 终止 / 创建实例（不能带启动脚本和 IAM 角色）/ 改实例类型 / 改标签 / 安全组规则 / 给卷建快照 / 修改卷（扩容、改类型、IOPS、吞吐；不能缩小）。
- **RDS**：启动 / 停止 / 重启 / 删除，修改实例（规格、存储扩容、备份保留天数）。修改时必须明确选「立即应用」还是「下个维护窗口」，卡片会写明什么时候停机、大约多久。
- **DynamoDB**：表的计费模式、预置容量、删除保护（不能删表）。
- **S3**：新建桶（始终打开「阻止公开访问」、禁用 ACL，可选开启版本控制）、桶标签 / 版本控制、删除空桶。
- **通用标签**：按 ARN 给资源加 / 删标签（Resource Groups Tagging API）；IAM、KMS、Secrets Manager 等资源的标签不能改（标签可能被 IAM 条件用来授权）。
- **Lambda**：内存、超时、环境变量。新值显示在卡片上（名称像密钥的除外），改环境变量一律算高风险；`NODE_OPTIONS`、`LD_PRELOAD`、代理之类会让运行时加载别的代码的变量不能设置。不能新建或删除函数。
- **ECS** 服务任务数，**Auto Scaling** 组期望容量，**CloudFormation**（先建 change set 展示变化，确认后才执行；助手写的模板不能带宏 / Transform、IAM 角色、UserData、内联策略，用服务角色部署的 stack 只能改参数）。

**列表以外的变更（通用请求）**：助手也可以提出上面列表以外的写操作（比如 `sns:Publish`、`ssm:SendCommand`、`sqs:DeleteQueue`）。应用不知道它们会改变什么，所以卡片上不是变更前后对比，而是**将原样发送的请求**：每个参数一行（嵌套的写成「A › B」，包括助手填的密码之类的值），下面可以展开「原始 JSON（实际发送的内容）」，注明「没有专用适配器，应用无法预知影响」和「不做漂移检查」；风险至少「高」，名称带 Delete / Terminate / Remove 等的算「破坏性」。第二步要手动输入操作名（如 `sns:Publish`）才能执行。支持 DryRun 的 EC2 操作先 DryRun，其他的做一次权限模拟。在账号的「AI 策略」里取消「其他服务」，就只能对勾选的服务提出变更（勾选的服务里没有适配器的操作照样是通用请求）。

**强确认（红色）**：IAM 提权（改策略、访问密钥、信任关系、建角色 / 用户）、修改本应用登录用的角色、关闭或修改 CloudTrail / GuardDuty / Config / Security Hub、组织和账号级操作、KMS 密钥、Secrets Manager、把数据公开（桶策略、ACL、公开快照 / AMI、函数 URL）、把 IAM 角色交给资源（`iam:PassRole`）、替换 Lambda 代码等，以前一律禁止，现在显示红色横幅「强确认 · 此类操作需要仔细核对」，列出操作类别（如「资源策略类变更」，只是分类，不是对后果的判断），必须输入操作名；生产账号还要连同账号 id 一起输入（如 `iam:AttachRolePolicy@123456789012`）。强确认没有「一直允许」。

**AI 影响分析（不熟悉的写操作）**：通用请求和强确认的卡片一出来，应用会用同一个模型另做一次只读分析：读取这次变更涉及的资源的当前状态（比如改桶策略时读现有策略、公开访问设置、标签；改安全组时读挂着它的网卡），和请求参数对比，写出「会改变什么」（策略按语义列出新增 / 移除的主体、操作、条件）、带依据的事实、标明的推断、受影响对象、能否撤销、建议风险、可信度和不确定的地方。卡片上标着「AI 分析（可能有误，请核对）」，分析完成前「确认执行」不可点（最多 90 秒，最多 8 次查询，只用默认放行的查询，不会弹审批卡）；分析失败或超时会写明原因，你自己核对参数后照常确认。分析只能**提高**风险（比如从「高」到「破坏性」，徽标带 ↑ 和原因），不能降低，也不能批准任何东西；它读到的策略、标签里的「指令」只被当作数据。它消耗的 token 计入本对话和本月用量。不想要可以在 AI 设置里关掉「写操作前自动做 AI 影响分析」，卡片就只显示请求本身。

账号策略仍然说了算：只读账号不会出现任何变更卡片；「AI 策略」里没勾选的服务、超过风险上限的（通用请求是「高」，强确认是「破坏性」，生产账号再升一级）直接被拒绝。执行用的是这个账号当前的 role，权限和你在 Console 里一样大。随时可以改回只读；改回后，还没确认的提案也不能执行。

**账号的 AI 策略**：打开「允许 AI 助手提出变更」后，账号设置里多出「AI 策略」：

- **服务**：只勾选允许助手提出变更的服务（默认全部）。「其他服务」包括所有没有专门适配器的服务（IAM、KMS、SNS、SQS、SSM……，都是通用请求或强确认）。
- **风险上限**：不限 / 最高「高」（禁止破坏性操作）/ 最高「中」/ 只允许「低」。超过上限的提案直接被拒绝，不会出现确认卡片。

策略在提案时检查，确认时和执行前再各查一次：提案之后收紧策略，那个提案就不能执行了。

**生产账号**：账号设置里勾选「生产账号」后，这个账号上的每个变更风险升一级，并且从「中」风险起都要输入资源名确认。资源本身带 `env=prod` 之类标签的也会升一级。风险上限按升级后的风险算，比如生产账号上限设「高」，本来是「高」的操作（升级后是「破坏性」）也会被拒绝。提案之后才改「生产账号」的设置，没确认的提案会作废，需要重新生成。

**审计**：每个提案、确认、取消、过期、执行结果、被拒绝的尝试，以及每次审批（请求、允许 / 拒绝 / 超时、「一直允许」的自动放行和撤销）都记在本机 `ai.sqlite` 的审计表里（不含凭证、对话正文和工具结果）。在应用里打开 AI 设置 →「AI 审计…」，可以按账号、时间、风险筛选，「复制为 JSON」；这里只显示摘要（操作、目标、风险、结果、Request ID），不显示参数。命令行：

```sh
npm run ai-audit                              # 过去 7 天，按账号、按天分组
npm run ai-audit -- --days 30                 # 或 --since 2026-10-01 / --since 14d
npm run ai-audit -- --account Prod --risk high,destructive
npm run ai-audit -- --csv > audit.csv         # 摘要导出（不含参数）
npm run ai-audit -- --json                    # 原始记录
```

在 AWS 侧，每次执行都能在 CloudTrail 里看到（DryRun 预检也会留下一条 `Client.DryRunOperation` 记录，权限模拟会留下 `SimulatePrincipalPolicy`）。

**数据与保留**：AI 设置 →「数据与隐私」：

- **对话保留**：一直保留（默认）/ 90 天 / 30 天 / 不保留（重启或退出应用时删除）。按最后一条消息的时间算。
- **审计记录保留**：默认 180 天（30–3650）。启动时和之后每天清理一次超过保留期的记录，未到期的不会删除；清理后偶尔压缩数据库文件。
- **删除全部 AI 数据**：删除所有账号的对话和用量记录。勾选「同时删除审计记录」时还要输入「删除审计记录」确认。API key 和设置不受影响。

**限制**：每条消息最多 40 次工具调用（一个脚本算 1 次，见上面的「运行脚本」）、20 轮往返、5 分钟（等你审批的时间不算；到上限时助手根据已查到的结果收尾回答）、3 张审批卡；每个账号同时最多 3 张待处理的审批卡，每个对话每分钟最多 6 次审批请求；每个对话最多 3 个待确认提案、每分钟 5 次提案；提案 10 分钟过期，重启应用后全部失效。确认之后的执行等待 AWS 最多 60 秒，失败不会自动重试。助手用的模型需要支持工具调用。

## 隐私与安全

- 凭证命令只在本机、用你自己的 shell 运行，等同于你在终端里手动执行它；应用不会把命令或它的输出发到任何地方。
- 凭证只保存在内存，从不写入磁盘（凭证命令本身存在账号列表里）。
- **AI 助手会把数据发给你选择的 LLM 服务商**：你的提问、账号名、account id、region、当前 Console 页面的地址（去掉令牌）和标题、助手读取的页面可见文字（脱敏后，可关闭），以及助手查到的资源名、标签、配置、日志、指标、成本等结果。AWS 凭证和 API key 不会发给模型。查询在本机用当前账号的凭证执行，结果先脱敏（密码、密钥、环境变量的值、启动脚本等）再发送。不想把这些数据交给第三方的话，可以用自建网关或本地模型（OpenAI 兼容端点）。用 AWS Bedrock 时，这些数据发到你自己 AWS 账号里所选 region 的 Bedrock，受该账号的 Bedrock 设置约束（例如是否开启了模型调用日志）；跨区域推理配置文件可能把请求路由到同一地理范围内的其他 region（`global.` 不限地理范围）。
- AI 助手不能自己执行任何变更，也不能自己通过审批：默认放行之外的调用都停下来等你在卡片上决定，执行的是应用冻结并校验过（hash）的参数，助手改不了。资源名、标签、日志里藏着的「指令」最多能让助手**请求**一次调用或**提出**一个变更，卡片会把它的真实内容摆在你面前。以前「一律拒绝」的保证换成了「一律先问你」：审批卡和强确认卡是最后一道防线，请看清参数再点。
- 助手的通用查询参数里带别的账号的 ARN、或者桶不属于这个账号时，一定会先问你（不能「一直允许」），因为这种请求会出现在对方能看到的日志里。
- LLM API key 默认经系统钥匙串加密后存盘（`ai-keys.json`，只有密文），也可以选仅内存或密钥命令。AI 对话记录和审计存在本机的 `ai.sqlite`，写入前会去掉凭证、API key 和密码形态的字符串；删除账号时它的对话一起删除。保留期和一键删除见上面的「数据与保留」。
- 应用自己的界面（渲染进程）是信任边界：确认和审批按钮只把提案 / 审批 id、你的选择和你输入的文字发给主进程，主进程重新检查一切再执行；但如果界面本身被攻破（例如 XSS），攻击者能做到你能点的一切。界面有严格的 CSP，不加载远程脚本。
- 所有数据（账号列表、最近访问、操作日志、AI 设置和对话）都存在本机 `~/Library/Application Support/aws-console-hub/`，不上报、无遥测。
- 外部链接只允许 http/https，Console 内页只允许 AWS 的域名（`amazon.com`、`aws.dev` 等）。

## 常见问题

- **提示「凭证命令执行失败」**：先在终端里直接运行同一条命令。最常见的原因是命令背后的登录态过期（例如 SSO 会话），重新登录后再试。错误提示显示在窗口右下角，8 秒后自动消失（悬停暂停），可以点「复制」拿到全文。
- **提示 `command not found`**：应用找不到命令。在终端里用 `command -v 命令名` 查到它的绝对路径，直接写进凭证命令；改了 shell 配置里的 `PATH` 后需要重启应用。
- **提示还没有设置凭证命令**：旧版本保存的基础账号没有凭证命令，应用会打开编辑窗口，填上命令即可。
- **跳转账号的会话比较短**：AWS 限制通过 role chaining 得到的会话最长 1 小时，应用会在到期前自动续上；续期同样需要凭证命令能正常运行。
- **⌘ 快捷键在 Windows / Linux 上**：改用 Ctrl，但未实测。
